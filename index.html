        Search guide

        Keyword and exact search

        Keywords must occur in the same record. Exact phrase search keeps word order. Both ignore letter case. A record is a text line, table cell, paragraph or JSON value.

        Ranked lexical search

        Enter a natural-language question. BM25 ranks records by matching words and document length. Any query word may match. This is a lexical fallback, not semantic inference. It does not infer answers or apply actuarial rules.

        Safe regex

        Use literals, a dot, character classes, ranges, \d, \w, \s and single-atom ?, * or +. Put ^ at the start or $ at the end to anchor a match. Example: retirement\s+age. Search ignores letter case. Groups, alternation, braces, lookaround and backreferences are rejected. A fixed operation budget stops costly queries.

        Read-only SQL

        SELECT * FROM records WHERE text CONTAINS 'retirement' LIMIT 20

        Use SELECT * FROM records with optional WHERE comparisons joined by AND, ORDER BY and LIMIT. Fields: text, sourceName, sourceHash, sourceId, score, line, row, column. Comparisons: =, !=, CONTAINS, LIKE. LIKE supports % and _. Quote text with single quotes. Mutations, joins and extensions are unavailable.

        Source locations

        Text uses source line and UTF-16 offsets. CSV uses row and column. Word uses document part, paragraph or table cell. Excel uses sheet and cell, retaining formulas as text. JSON uses pointers, not invented line numbers. View evidence shows nearby parsed records. Save original opens the unchanged source in your chosen local application.

        Graph and dates

        The document graph links each source to its parsed records. Unknown validity dates are shown as unknown; they are not evidence of applicability on a date. Temporal assertions require explicit supported evidence and review.

        Recovery and privacy

        IndexedDB, local storage or memory may be selected according to browser capability. Export a case before you close the browser. Recovery is best effort and tied to this browser and location. Restoring a package verifies source bytes and rebuilds records. Package hashes do not prove authorship. Exports are plaintext.

        Provisional outputs

        The R1 text is a source-linked drafting aid. It is not an official memo. The BSRS file is an internal nonexecutable representation, not documented official syntax. Missing templates, approved rules and official definitions remain release blockers.
